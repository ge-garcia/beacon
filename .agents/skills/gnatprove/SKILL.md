# SPARK and GNATprove

This skill holds only what a capable agent is likely to miss: features newer
than its training data, results that look green but are not, and restrictions
that force a redesign if found late. For everything else, the SPARK User's
Guide (UG) and Reference Manual (RM) for the installed release are
authoritative; read them.

"SPARK" may mean the language or the tool. "Run SPARK" means run
`gnatprove`; "update the SPARK" means edit the source.

## First: know the installed release

Run `gnatprove --version` once, then read
[references/versions.md](references/versions.md) to map it to a release and to
the matching manuals. Every link in this skill goes to the SPARK Pro 27.0
manuals; on another release, change `gnat-27.0` in the URL as that file says.

Material that needs a newer release than Pro 25 / FSF 15 is marked
**Requires:** with the first release that has it. On an older release, do
not use it; use the fallback given.

## Running gnatprove

- **Invocation.** In an Alire crate (`alire.toml` at the root), run
  `alr gnatprove -P <project.gpr> ...`. Otherwise use `gnatprove` if it is on
  `PATH`. Otherwise ask the user how to set up the environment: SPARK Pro
  installs usually need more than a `PATH` entry.
- **One run at a time.** Never run two `gnatprove` instances on the same
  project concurrently; they share output directories.
- **Long timeouts.** A run can take tens of minutes. Give the shell tool a
  timeout of at least 10 minutes for a unit or project, and capture the
  output (`2>&1 | tee gnatprove-run.txt`) so you never re-run only to re-read
  it. A run that timed out but printed output is still usable.
- **Always pass `--level`.** Without it, gnatprove does not use level 0: it
  runs cvc5 with `--steps=100` and no timeout. Start at `--level=0` or `1`;
  raise it only for checks the provers gave up on. Do not use 3 or 4 without
  the user's agreement.
- **Do not pass `-f` while iterating.** Incremental results are correct, and
  `-f` reruns everything in scope. Use it only for a final measurement that
  must be repeatable from a clean state, and say so when you report it.
- **Scope** with `-u file.adb` (a unit) or `--limit-subp=file.adb:NN` (one
  subprogram, `NN` = its declaration line). File names have no source
  directory prefix. Inside a generic, add `-U` and prefix the location with
  the instantiation's (`--limit-line=main.adb:12:gen.adb:5`).
  **Requires:** SPARK Pro 26 / FSF 16 or later for the prefixed location.
- Every switch is in the
  [command-line reference](https://docs.adacore.com/R/docs/gnat-27.0/spark2014/html/spark2014_ug/en/appendix/command_line_invocation.html);
  `gnatprove --help` is authoritative for the installed release.

## Results that look green but are not

- **The exit code does not mean "all proved".** All checks are proved when
  there are no check or warning messages. Take counts from the summary table
  in `gnatprove.out`, and check that every unit you meant to prove appears in
  it. The console line `Success: all checks proved (N checks).` /
  `Summary: X/Y checks proved` **Requires:** SPARK Pro 26 / FSF 16 or later.
- **`warning: no checks generated by GNATprove`** means nothing was analyzed,
  not that it is correct. So does a suspiciously low check count.
- **Only code marked `SPARK_Mode => On` is analyzed** when there is no
  configuration `SPARK_Mode`. Unmarked code is not checked for SPARK at all.
- **Generic instances.** A generic is analyzed only through instantiations
  that are in SPARK. `SPARK_Mode` cannot be an aspect of an instantiation;
  put `pragma SPARK_Mode;` before the `with` clauses of the instantiating
  unit. Then confirm checks appear `in instantiation at ...`. A check may hold
  for one instance and fail for another.
- **`--limit-line` on a line with no checks** prints nothing and no summary.
  Line numbers shift after every edit; confirm them.
- **Cached results can overstate the level.** A check proved earlier at a
  higher `--level` stays proved at a lower one. Before reporting the level a
  proof needs, run with `--report=provers`, which marks results taken from a
  cache. **Requires:** SPARK Pro 27 / FSF 17 or later. **Before SPARK Pro 27:** use a
  `-f` run at that level.
- **Bodies GNATprove cannot see** (imports, bodies not yet written or outside
  the analyzed files) are assumed `Global => null`, `Pre => True` and
  terminating. The `[assumed-global-null]` and `[assumed-always-terminates]`
  warnings name a missing model: write the `Global` and contracts.
- **`SPARK_Mode => Off` bodies** get a generated, unchecked, coarse `Global`
  (every write becomes `In_Out`; pointers become one `__HEAP`; writes through
  `in` access parameters and effects of indirect or dispatching calls can be
  missed).
- **A procedure that never returns satisfies any `Post`.** GNATprove checks
  that a procedure terminates only if it has `Always_Terminates`; add it
  when termination matters. Functions without `Side_Effects` are always
  checked to terminate.
- **`Builder'Switches` and `Builder'Default_Switches` are ignored** by
  gnatprove: `-gnat2022` or `-gnatX0` there must move to package `Compiler`.
  **Requires:** SPARK Pro 27 / FSF 17 or later. **Before SPARK Pro 27:** they are
  honored.
- **`--warnings=error` stops the analysis** after warnings; it does not turn
  them into errors.

## Proof integrity

Do not do these without the user's explicit agreement. Each makes a check go
away without proving it.

- `pragma Assume`, or `pragma Annotate (GNATprove, False_Positive | Intentional, ...)`.
- A ghost lemma or function with `Import` (an axiom: its `Post` is never
  proved).
- `SPARK_Mode => Off` on a body to get past proof.
- Weakening a `Pre`, `Post` or type the user specified, or clamping values
  (`X := T'Min (X, Max)`) to dodge a range check.

### GNAT language extensions in SPARK

Curated extensions need `-gnatX` or `pragma Extensions_Allowed (On)`;
experimental ones need `-gnatX0` or
`pragma Extensions_Allowed (All_Extensions)`. Check that the project's build
can use them first. See
[GNAT language extensions](https://docs.adacore.com/R/docs/gnat-27.0/gnat_rm/html/gnat_rm/gnat_rm/gnat_language_extensions.html).

- Curated: object declarations among statements; deep delta aggregates
  (`(S with delta A.X => 0, B (I).Y => 1)`); fixed lower bounds
  (`array (Natural range 0 .. <>) of T`); prefixed calls on untagged types;
  `'Constrained` on generic formal objects; `Static` intrinsic shifts;
  `Unsigned_Base_Range`. **Requires:** SPARK Pro 26 / FSF 16 or later:
  expression defaults for generic formal functions.
- Experimental: `X'Super`; `No_Dynamic_Accessibility_Checks`; inferred generic
  actuals. **Requires:** SPARK Pro 26 / FSF 16 or later: `finally`, `continue`, a
  standalone `use` implying `with`. **Requires:** SPARK Pro 27 / FSF 17 or later:
  `No_Raise`, `External_Initialization`, attribute subprograms
  (`function T'Integer_Literal (S : String) return T;`).
- Not in SPARK: string interpolation, conditional `when`, case pattern
  matching, constructors, destructors, `Size'Class`, `'To_String`, structural
  instantiation, `First_Controlling_Parameter`, `Default_Dispatching_Calls`.

## Restrictions that shape the design

Check these before choosing a design; GNATprove finds them only after the code
is written.

- **No controlled types in SPARK code.** A private type may have a controlled
  full view in a private part with `SPARK_Mode => Off`; SPARK code still gets
  no finalization, so release resources explicitly.
- **No user-defined indexing or references** (`Constant_Indexing`,
  `Variable_Indexing`, `Implicit_Dereference`) and no
  `Ada.Iterator_Interfaces`; iterate with the `Iterable` aspect.
- **Discriminants are discrete** (no access discriminants), and a derived type
  cannot declare discriminants.
- **Ownership**: pointer structures are trees and lists; no cycles, no
  sharing, and borrowers cannot be stored in data structures. For sharing or
  cycles, use array indexes or `SPARK.Pointers` from SPARKlib. A derived
  tagged type cannot have a component of a named access-to-variable type.
  An `in out` parameter of a named access-to-variable type is moved, not
  borrowed: the callee may repoint it.
- **Callbacks**: `'Access` cannot be taken on a subprogram with global inputs
  or outputs, except as the actual of a `Higher_Order_Specialization`
  function, or for an access type annotated
  [`Handler`](https://docs.adacore.com/R/docs/gnat-27.0/spark2014/html/spark2014_ug/en/appendix/additional_annotate_pragmas.html#annotation-for-handlers)
  (synchronized globals only; SPARK code cannot call it). A call through a
  subprogram pointer is assumed possibly nonterminating.
- **Exceptions**: only explicitly raised exceptions can be handled; failed
  run-time checks are proved impossible, not handled. Handlers cannot have a
  choice parameter (`when E : others`).
- **Tasking**: Ravenscar or Jorvik with `Partition_Elaboration_Policy
  (Sequential)`; tasks never terminate; no task entries; a task's or
  protected operation's `Global` names only synchronized state. See
  [Concurrency](https://docs.adacore.com/R/docs/gnat-27.0/spark2014/html/spark2014_ug/en/source/concurrency.html).
- **Volatile and addresses**: `'Address` only in representation clauses;
  effectively volatile objects only at library level. A volatile read may
  appear only in a non-interfering context (whole assignment, object
  initializer, an actual whose formal is of a non-scalar volatile type), not
  inside a larger expression.
- **`SPARK_Mode` placement**: only on library-level units or as a
  configuration pragma; never on an instantiation. A generic marked with
  `SPARK_Mode` cannot be instantiated inside a subprogram body.
- **Tagged types**: an overriding operation's `Pre'Class` must be weaker and
  its `Post'Class` stronger than the overridden one's, and GNATprove checks
  it. Dispatching calls are verified against the class-wide contracts. Write
  the root type's class-wide contracts first. See
  [Object Oriented Programming and LSP](https://docs.adacore.com/R/docs/gnat-27.0/spark2014/html/spark2014_ug/en/source/object_oriented_programming.html).

## Commonly misremembered

- **`--mode` is not one chain.** `check` < `check_all` < `flow`. `prove` is
  `check_all` plus flow's uninitialized-read check, without the data- and
  flow-dependency checks. `all` (the default) is both.
- **`pragma Assert_And_Cut`** forgets only what was modified or tested in its
  enclosing statement sequence, not all prior context; a block scopes it.
- **`Default_Initial_Condition`** with no argument promises full default
  initialization; `=> null` means not fully initialized.
- **Ghost code may run** when it is enabled, by `-gnata` or by
  `pragma Assertion_Policy` (for kind `Ghost` or for its assertion level).
  Ghost code is not always stripped.
